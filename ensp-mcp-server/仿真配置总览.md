这份文档用于集中整理当前 eNSP 工程中的关键配置、设备角色、链路关系、地址规划、出口策略和已验证结果，方便后续继续维护、排障或答辩展示时快速理解整个仿真。

## 2. 整体拓扑结构

当前仿真整体可以理解为 5 层：

1. 核心与三层网关层
2. 出口安全与互联网层
3. 汇聚层
4. 接入层
5. 终端与无线覆盖层

### 2.1 核心与网关

- `Core1-HNCU`：主核心，承担大部分 VLAN 网关、DHCP、默认路由
- `Core2-HNCU`：备核心，承担 VRRP 备份
- `AC-HNCU`：无线控制器，负责 FIT AP 注册与 CAPWAP 管理

### 2.2 出口与互联网

- `FW1`：核心与出口路由之间的安全边界
- `AR1`：边界路由器，承担公网口源 NAT
- `ISP1`、`ISP2`：模拟互联网与上游运营商

### 2.3 宿舍与教学接入

- 男生宿舍无线链路：`AGG-Dorm-Male -> ONU-Dorm-Male -> POE5 -> LSW23 -> AP9/AP10/AP11`
- 男生宿舍有线支路：`AGG-Dorm-Male -> S5 -> PC5`
- 教学区有线支路：`Core/汇聚 -> CE8 -> S4 -> PC4`
- 女生宿舍无线链路：`AGG-Dorm-Female -> ONU-Dorm-Female -> POE6 -> LSW24 -> AP12/AP13/AP14`

### 2.4 XGPON 仿真说明

工程中没有使用真实 OLT/OBD/ONU 模型，而是采用交换机对象进行等效表达，用于展示接入层级关系。当前宿舍区重点业务链路已经按可运行方式梳理，尤其男生宿舍无线侧已调整为可联通的直通方式。

## 4. 核心与出口关键配置

## 4.1 Core1-HNCU

`Core1-HNCU` 是当前全网的主要业务入口，承担：

- 各 VLAN 三层网关
- DHCP 地址池
- AP 管理网关
- 指向出口的默认路由

关键点：

- 全局开启 `dhcp enable`
- 为 `VLAN201/202/203/301/401/501` 配置本地地址池
- 默认路由指向 `172.16.200.9`
- 出口下一跳通过 `GE1/0/3`

关键路由关系：

- `0.0.0.0/0 -> 172.16.200.9`
- `GE1/0/3 = 172.16.200.10/30`

### 4.1.1 DHCP 地址池

- `VLAN201-Teacher`
- `VLAN202-Student`
- `VLAN203-Guest`
- `VLAN301-Teaching`
- `VLAN401-Dorm`
- `VLAN501-Office`

### 4.1.2 访客隔离 ACL

`Core1-HNCU` 上配置了 `ACL 3000`，用于限制 `VLAN203` 对部分内部网段的访问，保留外部访问能力。

## 4.2 Core2-HNCU

`Core2-HNCU` 作为主备中的备核心，接口和 VLAN 规划与 `Core1-HNCU` 基本一致，但优先级较低。

## 4.3 AC-HNCU

`AC-HNCU` 负责：

- AP 预注册
- CAPWAP 建链
- AP 状态管理

当前已确认：

- `AP9`、`AP10`、`AP11` 为 `nor`
- `AP12`、`AP13`、`AP14` 目前仍为 `idle`

## 4.4 FW1

`FW1` 位于核心和边界路由器之间，承担安全域与路由转发。

接口与地址：

- `GE0/0/0 = 172.16.200.9/30`，朝向 `Core1-HNCU`
- `GE1/0/0 = 172.16.200.6/30`，朝向 `AR1`

安全域：

- `trust`：核心侧
- `untrust`：出口侧

安全策略：

- `trust -> untrust` 允许
- `untrust -> trust` 允许

静态路由：

- 默认路由到 `172.16.200.5`
- `10.0.0.0/8` 回程指向 `172.16.200.10`

说明：

- `FW1` 当前不承担最终公网 NAT
- 它主要负责安全域分界与三层转发

## 4.5 AR1

`AR1` 是真正的出口 NAT 设备。

接口与地址：

- `GE0/0/0 = 172.16.200.5/30`，连接 `FW1`
- `GE0/0/1 = 8.8.8.2/24`，连接 `ISP1`

静态路由：

- 默认路由：`0.0.0.0/0 -> 8.8.8.1`
- 回内网路由：`10.0.0.0/8 -> 172.16.200.6`

已补充的关键 NAT：

- `ACL 2000`：允许 `10.0.0.0/8`
- `GE0/0/1` 配置 `nat outbound 2000`

作用：

- 将校园内部业务地址统一转换为 `8.8.8.2`

## 4.6 ISP1 / ISP2

模拟上游互联网与进一步外部转发：

- `ISP1` 连接 `AR1`
- `ISP2` 连接 `ISP1`

作用：

- 提供可验证的外网路径
- 验证宿舍有线、无线终端是否真正可出网

## 10. 推荐的排障顺序

后续如果某条业务链路不通，建议按以下顺序排查：

1. 看物理口是否 `up/up`
2. 看接入口是否进入正确 VLAN
3. 看上联 trunk 是否放通目标 VLAN
4. 看交换机是否学到终端或 AP 的 MAC
5. 看核心是否学到 ARP 或 DHCP 租约
6. 看是否能 ping 通对应网关
7. 看是否能 ping 通 `AC` 或出口测试地址
8. 最后检查 `FW1`、`AR1` 的路由与 NAT
